# Governance

## Roles

Maintainers steward releases, triage issues, review pull requests, and protect
the project's authorized-research boundary. Contributors may propose code,
documentation, targets, and research workflow improvements through issues and
pull requests.

## Decisions

Routine changes are accepted after maintainer review and passing CI. Changes to
`SECURITY.md`, `safety.py`, target authorization, or prohibited capabilities
require explicit human-maintainer approval and a written rationale in the pull
request. When consensus is not reached, maintainers make and document the
final decision.

## Roadmap and participation

The current priorities live in [ROADMAP.md](ROADMAP.md). Use a GitHub issue for
actionable work and Discussions for design questions or research methodology.
Issues labelled `good first issue` and `help wanted` are the preferred entry
points for new contributors.

## Review expectations

Pull requests should be focused, tested, documented where user behavior
changes, and responsive to review feedback. Maintainers aim to acknowledge new
issues and pull requests within seven days; this is a goal, not an incident
response SLA.
